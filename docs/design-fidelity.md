### 1.4 Typography

- **ฟอนต์ default ของ TextTheme = IBM Plex Sans Thai** (400/500/600) — สแต็ก body ใน design เป็นไทยนำ
- **Space Grotesk** (400/500/600/700) ใช้ **เฉพาะจุดที่ design ระบุ**: ตัวเลขจำนวน, บรรทัด SKU, แบรนด์ TCL, keypad, badge/role pill, นาฬิกา
- ⚠️ ห้ามตั้ง Space Grotesk เป็น default แล้ว fallback ไทย — จะทำให้คำละติน/ตัวเลขในเนื้อความไทย ("Employee ID", ชื่อ "Tcl S.") ผิดฟอนต์ทั้งแอป
- ⚠️ **ห้ามใส่ letterSpacing กับข้อความสคริปต์ไทย** (`.08–.14em` ใน design เป็นของ Latin/ตัวเลขเท่านั้น) — ทำ shaping ไทยพัง
- ฟอนต์ bundle ใน assets (ห้าม fetch runtime) + StrutStyle ต่อ scale step กัน baseline ไทย/ละตินเหลื่อมและวรรณยุกต์ (◌้ ◌์) โดนตัด
- **Golden tests ทุกจอด้วยสตริงวรรณยุกต์หนัก** เป็น CI gate

Type scale (px/weight): `30/700` เลขคงเหลือการ์ดสแกน (lh .95, ls -.02em) · `26/600` หัวเรื่อง (lh 1.2) · `24/700` เลขผลค้นหา + แบรนด์ · `23/600` หัว sheet · `21/500` keypad · `19/500` empId input (ls .14em) · `18/600` ค่า stat/ช่องนับ/เลขระบบ · `17/600` ชื่อสินค้า/สมาชิก (lh 1.25) · `16/600` CTA หลัก · `15` CTA รอง + input · `13.5–10` ตามตาราง token (toast 13, subtitle 12.5, label 12, meta 11.5, SKU 11 ls .08em, unit/tab 10.5, role header 10 uppercase ls .12em)

| ชื่อ | สเปค | Flutter mapping |
|---|---|---|

## 2. โครงหน้าจอและทุกสถานะ

### 2.1 Login "เข้าสู่ระบบ"

- โลโก้ tile 54×54 r17 gradient + แบรนด์ **TCL** (Space Grotesk 700 24) + ซับ "เข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่าน"
- การ์ดแก้ว: ช่อง **ชื่อผู้ใช้ · Username** (h52 r16, ไอคอนคน `#84BAF3`, ls .14em token เดิมของ empId) → ช่อง **รหัสผ่าน · Password** (h52 r16, ปิดบังตัวอักษร, ≤128, body 15) → ปุ่ม **เข้าสู่ระบบ** gradient + ลูกศร → บรรทัดข้อความสถานะ
  - ⚠️ **ไม่มี keypad 12 ปุ่ม / ช่อง PIN 6 เซลล์ / hint `{n}/6` อีกแล้ว** — ล็อกอินคือข้อมูลรับรองของ ERP (`menuuser`) ซึ่งพิมพ์ด้วยแป้นตัวเลขล้วนไม่ได้ · โทเคน `hPinCell`/`rPinCell`/`hKeypadKey`/`rKeypad`/`keypadKey()` ถูกลบไปพร้อมกัน · `errorBorder` ย้ายไปเป็นขอบแดงของ `FieldBox` แทนที่จะหายไปกับเซลล์
  - **ด่านกันเครื่องยิงบาร์โค้ดที่ช่องรหัสผ่าน:** เครื่องยิงเป็น HID keyboard-wedge — เหนี่ยวไกเผลอขณะช่องนี้โฟกัสอยู่จะพิมพ์บาร์โค้ดลงช่องที่บดบังไว้เงียบ ๆ แล้วโดน throttle โดยไม่มีคำอธิบาย ช่องจึงห่อด้วย `Focus.onKeyEvent` ที่ป้อนคีย์เข้า `HandheldScanBuffer` ตัวเดียวกับจอสแกน: คีย์ที่อยู่ใน**สายรัวที่พิสูจน์แล้ว** (ช่องไฟ ≤ `burstGap`) ถูกกลืนทั้งชุด + ล้างช่องทั้งช่อง + เตือนหนึ่งครั้งต่อการยิงหนึ่งใบ · ⚠️ ด่านคือ `swallow` ไม่ใช่ "รหัสจบแล้ว" — คนที่พิมพ์รหัสผ่านเองแล้วกด Enter ก็ทำให้บัฟเฟอร์คืนรหัสจบเหมือนกัน ล้างตรงนั้น = ลบรหัสที่เขาเพิ่งพิมพ์ทิ้ง
- Chips ล่าง: `WH-BKK-02` `v4.0` (ตัด chip `PIN 000000` — ดู §6)
- **สถานะ:** ปกติ / ไม่พบชื่อผู้ใช้ → shake + ข้อความ **"ไม่พบชื่อผู้ใช้นี้ · unknown user"** สี BAD + ขอบช่องแดงทั้งสองช่อง / รหัสผ่านผิด → ล้างช่องรหัสผ่าน + **"รหัสผ่านไม่ถูกต้อง ลองอีกครั้ง"** (ข้อความมาจาก server · error code เดิม `UNKNOWN_EMPLOYEE`/`INVALID_PIN` ไม่เปลี่ยน) / พิมพ์อะไรก็ล้าง error / ตรวจพบการสแกน → ล้างช่อง + **"ตรวจพบการสแกนขณะกรอกรหัสผ่าน · กรุณาพิมพ์ด้วยตนเอง"** บนบรรทัดสถานะเดียวกัน (จอนี้อยู่นอก AppShell จึงไม่มีชั้น toast ให้วาด)
- สถานะเพิ่มของ production (ออกแบบเพิ่ม §7): โดน throttle, เครื่องนี้ต้องต่อเน็ตครั้งแรก — **ตัด "ต้องเปลี่ยน PIN ครั้งแรก" ทิ้งแล้ว** (รหัสผ่านเป็นของ ERP เปลี่ยนที่ ERP แล้ว sync รอบถัดไปตามมาเอง จอ `ChangePinScreen` ถูกลบทั้งไฟล์)

### 2.3 แท็บสแกน

- กรอบกล้อง r28 บน `#121C27`: วิดีโอเต็มกรอบ, radial glow ฟ้า, **เส้นเลเซอร์กวาด** (`#A6D2FB` + เงาเรือง), **กรอบมุม 4 ชิ้น** 30×30 หนา 3px r14 (ตำแหน่ง: ซ้าย/ขวา 14%, บน/ล่าง 26% — ใช้เป็น `scanWindow` ROI ของ mobile_scanner ด้วย), **ป้ายสถานะ** มุมบนซ้าย (pill + จุดเขียว pulse + ข้อความ) , **FAB คอลัมน์** มุมล่างขวา: ปุ่มกล้อง (glow ตอนปิด — **เฉพาะโหมด CAMERA** ดูหัวข้อโหมดสแกนถัดไป) + ปุ่มค้นหา (→ แท็บค้นหา, มีทั้งสองโหมด)
- ขนาดกล้อง (`scanLayout`): `sheet` = เต็มจอตอนยังไม่สแกน → หด 186px เมื่อมีรายการแรก; `split` = คงที่ 250px; min-height 190 ทุกกรณี
- **โหมดสแกน (ส่วนขยาย §7 ข้อ 10 — design ต้นแบบไม่มี):** กรอบกล้องมี 2 หน้าตาตาม `scanMode` โดยไม่ย้ายชิ้นส่วนใดออกจากกรอบ (ป้ายสถานะอยู่ในกรอบ ลบกรอบทิ้งไม่ได้)
  - **HANDHELD** (ค่าเริ่มต้น) — สองขนาดตาม "มีรายการที่สแกนแล้วหรือยัง" (ภาษาเดียวกับที่โหมด CAMERA หดกรอบเมื่อมีรายการแรก):
    - **ยังไม่มีรายการ**: กรอบ 190px · ไม่มีเลเซอร์ · ไม่มีกรอบมุม · ไม่มีปุ่มกล้อง · กลางกรอบเป็น hero ไอคอนบาร์โค้ด 28px (`accentBright`) + **"ยิงบาร์โค้ดได้เลย"** + **"เล็งฉลากแล้วเหนี่ยวไก — ไม่ต้องแตะจอ"**
    - **มีรายการแล้ว**: หดเป็น **แถบแนวนอน `hHandheldStrip` = 56px** (พื้น `cameraViewportBg` + `b13` + `rCard`) — ไอคอนบาร์โค้ด 20px `accentBright` · **ป้ายสถานะ** (pill เดิม จุด pulse + ข้อความ ชิดซ้าย ย่อเองเมื่อยาว) · **FAB ค้นหา** 46px ชิดขวา · ไม่มี `MobileScanner` อยู่ในจอเลย (โหมดนี้บังคับ `camOn=false` อยู่แล้ว ไม่มีสถานะกล้องที่ยังวิ่งให้เสียตอน unmount — กลับเข้าโหมด CAMERA แล้ว preview mount ใหม่ และโหมดนั้นไม่เปิดกล้องเอง) — **deviation ที่บันทึกแล้ว ดู §6 แถว 10**
  - **CAMERA**: เหมือน design ต้นแบบทุกประการ (เลเซอร์ + กรอบมุม + ปุ่มกล้อง + ขนาดตาม `scanLayout` ด้านบน) — เลเซอร์เกทด้วย `camOn` ไม่ใช่โหมด จึงเลิกกวาดตอนกล้องยังปิด (จุดที่จอโกหกมาแต่เดิม)
  - `scanWindow` ROI ยังส่งให้ mobile_scanner เสมอทั้งสองโหมดแม้ไม่วาดกรอบมุม — สลับกลับมา CAMERA แล้วพฤติกรรมกล้องต้องเหมือนเดิมเป๊ะ
- **แถบสลับโหมด** (ระหว่างกรอบกล้องกับแถบเครื่องมือ): สวิตช์ 2 ช่องเต็มความกว้าง **เครื่องยิง / กล้อง** — token เดียวกับ `_ViewSwitch` ของจอผู้ดูแล (`s09` + `b13` + `rTabBar`; ปุ่ม h38 `rTabButton` + `activeTabGradient`/`onAccent` เมื่อ active, `tMuted` เมื่อไม่ active) + ไอคอน 16px นำหน้าข้อความ · สลับได้จากปุ่มฮาร์ดแวร์ที่ผูกไว้ด้วย (toast **"โหมดเครื่องยิง · handheld"** / **"โหมดกล้อง · camera"** เฉพาะตอนสลับด้วยปุ่ม เพราะคนกดปุ่มข้างอาจไม่ได้มองจอ)
- เข้าโหมด CAMERA **ไม่เปิดกล้องเอง** — ผู้ใช้แตะ FAB ที่กำลัง glow เอง (ปุ่มฮาร์ดแวร์กดเผลอได้ ต้องไม่มีทางเรียก permission dialog ขึ้นเอง)
- แถบเครื่องมือ: ซ้าย **"ยังไม่มีรายการที่สแกน"** / **"สแกนแล้ว {n} รายการ"**; ขวา ปุ่ม **"ล้าง"** (เมื่อมีรายการ) — ปุ่มจำลอง 1/2/3 ของ demo แทนด้วยปุ่มกรอกบาร์โค้ดมือ (§6)
- **การ์ดผลสแกน** (เรียงใหม่สุดบน, สแกนซ้ำ = เด้งขึ้นบน + เวลาใหม่, เปิดขยายได้ทีละใบ):
  - แถบ tone 8×40 · `{SKU} · {HH:MM}` · ชื่อไทย 17/600 · `{สถานะ} · {ตำแหน่ง}` · ขวา: เลขคงเหลือ 30/700 สี tone + "{หน่วย} คงเหลือ"
  - ขยาย: แถบระดับสต็อก (สูตร `bar = clamp(3,100, round(onHand/(rop×3)×100))%` — ⚠️ production กัน `rop<=0` → ซ่อนแถบ) + 3 tiles **จอง / พร้อมขาย / จุดสั่งซื้อ** (พร้อมขาย = onHand−reserved, ⚠️ ติดลบ → แสดง 0 + flag) + spec rows (**ผู้ผลิต · Vendor / ล็อต · Lot / นับครั้งล่าสุด · Last count** — เมื่อ `itemCard='spec'`) + ปุ่ม **"นับสต็อกรายการนี้"** (gradient) / **"นำออก"** + ท้าย `{nameEn} · อัปเดต {เวลา}`
- Empty state: **"สแกนต่อเนื่องได้เรื่อย ๆ ทุกรายการที่อ่านได้จะเรียงไว้ด้านล่างพร้อมยอดคงเหลือ"** + **"แตะรายการเพื่อดูรายละเอียดเพิ่ม"**
- Role gate: viewer กด "นับสต็อกรายการนี้" → toast **"สิทธิ์ viewer นับสต็อกไม่ได้"** ไม่นำทาง

### 2.4 แท็บค้นหา

- ช่องค้นหา h52 r18 placeholder **"ชื่อสินค้า / SKU / บาร์โค้ด"** + บรรทัด **"{n} รายการ"**
- ค้น substring แบบ case-insensitive บน name+nameEn+sku+barcode — ⚠️ production: debounce + จำกัดผล (แสดง 100 จาก N) + `ListView.builder`
- การ์ดผลลัพธ์: แถบ tone · SKU · ตำแหน่ง · ชื่อไทย · ชื่ออังกฤษ · เลขคงเหลือ 24/700 สี tone + หน่วย
- แตะผลลัพธ์ → เข้ารายการสแกนแบบขยาย + สถานะกล้อง **"เลือกจากการค้นหา · {SKU}"** (พฤติกรรม handoff ตาม design เป๊ะ)
- Empty: **"ไม่พบสินค้าที่ตรงกับคำค้น"** / "No matching items"

### 2.5 แท็บนับสต็อก

- การ์ดรอบนับ: **"โซน {zone} · {sessionId}"** + **"นับแล้ว {done}/{total}"** + แถบ progress gradient ฟ้า→เขียว
- แถวนับ: SKU · ตำแหน่ง · ชื่อ · ขวา label **"ระบบ"** + เลข frozen qty · stepper **− [ช่องกรอก "นับได้"] +** (44×44 r14, ช่อง w88 focus ขอบ `#84BAF3`, ตัวเลขเท่านั้น, − ไม่ต่ำกว่า 0)
- **Pill variance (ข้อความเป๊ะตาม design):** ยังไม่กรอก → **"ยังไม่ได้นับ"** (เทา) · diff=0 → **"ตรงกับระบบ"** (OK) · diff>0 → **"เกิน +{diff}"** (WARN) · diff<0 → **"ขาด {diff}"** (WARN, ตัวเลขติดลบในตัว เช่น "ขาด -3")
- ปุ่ม **"ส่งผลการนับ"** เต็มกว้าง h54 gradient — ยังไม่นับ → toast **"ยังไม่มีรายการที่นับ"**; นับแล้ว → toast **"ส่งผลการนับ {n} รายการแล้ว"** (enqueue เข้า outbox — ดูข้อตัดสินใจ #4 ใน §6)

### 2.6 แท็บสมาชิก

- แถวสมาชิก: avatar สี role อักษรย่อ (grapheme-safe) · ชื่อ 17/600 · `{empId} · {กะ}` · **role pill** ADMIN (ฟ้า) / STAFF (เขียว) / VIEWER (เทา)
- แตะ pill = วน role admin→staff→viewer (admin เท่านั้น; ไม่ใช่ admin → toast **"ต้องมีสิทธิ์ผู้ดูแลเพื่อแก้ไขสิทธิ์"**) + กติกาเพิ่มของ production: กันลด role จนไม่มี admin เหลือ
- Hint: **"แตะที่สิทธิ์เพื่อสลับ admin / staff / viewer (เฉพาะผู้ดูแล)"**
- ปุ่มล่าง: **"ออกจากระบบ"** เต็มกว้าง (ปุ่ม "เพิ่มสมาชิก" ถูกตัดออก — ดู §2.7)

### 2.7 Bottom sheet "เพิ่มสมาชิกใหม่" — **ตัดออกแล้ว**

- รายชื่อสมาชิกมาจาก sync ผู้ใช้ ERP (`menuuser`) อย่างเดียว แอปสร้างคนใหม่ไม่ได้แล้ว
  `POST /members` และ `POST /members/:empId/reset-pin` ถูกลบทั้งฝั่ง server และฝั่งแอป
  (ปุ่มที่กดแล้วได้ 404 แย่กว่าไม่มีปุ่ม — ดู §6 แถว 9) · เพิ่ม/แก้คนต้องทำที่ ERP
- mutation เดียวที่เหลือในแท็บสมาชิกคือ **แตะ role pill** → `PATCH /members/:empId/role`
- ⚠️ กติกาที่ยังบังคับกับ sheet ที่เหลือทุกตัว (ยืนยันส่งผลนับ / กรอกบาร์โค้ดมือ):
  **implement เป็น Stack layer ในต้นไม้เดียวกัน (ไม่ใช้ `showModalBottomSheet`)** หรือ toast
  ผ่าน root Overlay — ไม่งั้น toast validation จะจมใต้ barrier มองไม่เห็น

### 5.3 State machine `camStatus` (สตริงเป๊ะจาก design + เพิ่มของจริง)

| สถานะ | ข้อความ |
|---|---|
| ปิดอยู่ (เริ่มต้น/หลัง sign-out/เข้าโหมดกล้อง) | "กล้องปิดอยู่ · แตะไอคอนกล้อง" |
| ปิดเอง | "กล้องปิดอยู่ · camera off" |
| กำลังสแกน | "กำลังค้นหาบาร์โค้ด · scanning" |
| ไม่ได้รับ permission | "เปิดกล้องไม่ได้ · ใช้ปุ่มจำลอง" → ⚠️ ปรับท้ายเป็น "…ใช้การค้นหา/กรอกรหัส" (ปุ่มจำลองไม่ ship — ข้อความ 2 จุดนี้ต้องแก้ตาม §6) |
| decoder ใช้ไม่ได้ (เครื่องไม่มี GMS) | "เบราว์เซอร์นี้อ่านบาร์โค้ดไม่ได้ · …" → ปรับคำเป็น "เครื่องนี้…" |
| ไม่พบรหัส | "ไม่พบรหัส {code}" (+ toast "ไม่พบบาร์โค้ดนี้ในคลัง · not found") |
| เจอสินค้า | "พบสินค้า · {SKU}" / "เลือกจากการค้นหา · {SKU}" |
| เพิ่ม: resume จาก background | กลับสู่สถานะก่อนหน้า (`camOn` จำไว้) — นโยบาย lifecycle ดู architecture.md §9 |
| เพิ่ม: โหมดเครื่องยิง (§2.3) | "พร้อมยิงบาร์โค้ด · handheld" |

⚠️ แถวสุดท้าย **ไม่ได้มาจาก `camStatus`** แต่มาจาก `scanMode`: getter `camStatusText` คืนค่านี้ตรง ๆ เมื่อ `scanMode == handheld` **และ `!camStatus.isFailure`** (ไม่มีจุดไหนเขียนค่านี้ผ่าน `setCamStatus()` เลย) ผลคือ "กล้องปิดอยู่ · แตะไอคอนกล้อง" กลายเป็นสตริงที่ไปไม่ถึงในโหมดเครื่องยิงโดยโครงสร้าง ไม่ใช่แค่ตั้งใจไม่เขียนมัน — ลำดับด่านคือ `camStatusOverride` → `isFailure` → `handheldReady` โดย `camStatusOverride` (ไม่พบรหัส / เจอสินค้า) ยังชนะทุกโหมดเหมือนเดิม

⚠️ **กล้องที่ขัดข้องทะลุขึ้นป้ายได้ทั้งสองโหมด — ไม่ถูกกลบ:** `CamStatus.isFailure` เป็นจริงกับ `permissionDenied` และ `detectorUnavailable` เท่านั้น กล้องที่ **แค่ปิดอยู่** ยังถูกกลบด้วย "พร้อมยิงบาร์โค้ด" ตามเดิม (ไม่ใช่เรื่องที่ต้องรายงานในโหมดที่ไม่ได้ใช้กล้อง) แต่กล้องที่ **สั่งปิดไม่ลง** ยังยึดเซ็นเซอร์อยู่ และเครื่องยิงก็พลอยอ่านไม่ได้ (Bluebird คืน `BBAPI_ERROR_BARCODE_CAMERA_USED = -9`) กลบไว้เท่ากับคนเหนี่ยวไกแล้วไม่มีอะไรเกิดขึ้นโดยไม่มีคำอธิบายอยู่ที่ไหนเลยทั้งจอ — โหมดเครื่องยิงไม่มีทั้งปุ่มกล้องและ preview ให้ดูว่าดับหรือยัง

⚠️ **โหมดเครื่องยิงมี toast คู่กับป้ายเสมอ:** ป้ายอยู่มุมบนซ้ายของกรอบกล้อง ซึ่งเป็นพื้นที่ที่คนกำลังเล็งฉลากบนชั้นไม่ได้มอง `_reportCameraFailure` จึงยิง `flash(CamStatus.detectorUnavailable.text)` เพิ่มเมื่อ `scanMode == handheld` — **สตริงเดียวกับป้าย ไม่ใช่ข้อความใหม่ให้เบี่ยงจากกัน** · โหมดกล้องไม่มี toast นี้ (ป้ายอยู่บนภาพที่ผู้ใช้จ้องอยู่แล้ว และ preview ที่ดับไปก็เห็นเอง) · ส่วนแขนง `permissionDenied` มี toast "ไม่ได้รับอนุญาตใช้กล้อง · camera blocked" ของตัวเองอยู่แล้วทั้งสองโหมด · ทั้งสองครึ่ง (ป้าย + toast) ต้องอยู่ด้วยกัน — toast อย่างเดียวหายไปใน ~2 วินาทีแล้วจอกลับไปโกหกว่า "พร้อมยิงบาร์โค้ด"

พฤติกรรมสแกน: **สั่น (35ms-equivalent) ทุก decode ทั้งเจอและไม่เจอ** · dedup-prepend (สแกนซ้ำเด้งขึ้นบน + เวลาใหม่) · `DetectionSpeed.normal` + cooldown ต่อ code ~1.5–2 วิ (ห้าม `noDuplicates`)

## 7. Design extensions ที่ต้องออกแบบเพิ่ม (สถานะที่ demo ไม่มีแต่ production ต้องมี)

ทำด้วยภาษา token ของ TCL เดิมทั้งหมด — ลำดับตามความจำเป็นก่อน implement:

1. **จอ pending-review** — งานที่ถูก reject ตอน sync (เช่น "สิทธิ์ถูกเปลี่ยน — รอผู้ดูแลตรวจสอบ", "รอบนับถูกปิดแล้ว") + ปุ่ม retry/ทิ้ง
2. **ตัวชี้สถานะซิงค์** — queue-depth badge, ป้าย "ข้อมูล ณ HH:MM" (พื้นที่ว่างบนกรอบกล้องจำกัด — เสนอวางในแถบเครื่องมือใต้กล้อง), สถานะ online/offline
3. **วงจรรอบนับ** — ไม่มีรอบ active ("ยังไม่มีรอบตรวจนับ — รอผู้ดูแลเปิดรอบ"), รอบถูกปิดระหว่างออฟไลน์, ใครนับล่าสุดต่อแถว, ตัวชี้ CONFLICT
4. **วงจรรหัสผ่าน** — โดน throttle ("ลองใหม่ใน {n} วินาที"), "การเข้าสู่ระบบครั้งแรกต้องเชื่อมต่อเครือข่าย" · ~~เปลี่ยน PIN ครั้งแรก / admin reset~~ **ตกไปแล้ว** (รหัสผ่านเป็นของ ERP แก้ที่ต้นทาง)
5. ~~**จอแสดง PIN เริ่มต้น** หลังเพิ่มสมาชิกสำเร็จ~~ — **ตกไปแล้วพร้อมกับ sheet เพิ่มสมาชิก** (§2.7 / §6 แถว 9)
6. **First-run** — ดาวน์โหลด item master ครั้งแรก (progress/fail/partial)
7. **ช่องกรอกบาร์โค้ดมือ** — เมื่อกล้องใช้ไม่ได้/ฉลากเสีย
8. **จอ update APK** — prompt จาก `/meta` minVersion (blocking vs ข้ามได้)
9. **รายการนับขนาดจริง** — ค้นหาในรอบ + จัดกลุ่มโซน + virtualization
10. **โหมดสแกนที่เลือกได้ + ปุ่มฮาร์ดแวร์ผูกได้** (ทำแล้ว) — เครื่องยิง/กล้อง สลับได้จากแถบในจอสแกน (§2.3) หรือปุ่มที่ผูกไว้ผ่าน admin pane **"ปุ่มเครื่อง"** (จับคีย์สด + ปฏิเสธถาวรสำหรับปุ่มพิมพ์อักขระ/Enter/ปุ่มระบบ/ปุ่มที่มาเป็นชุด) · ค่าเริ่มต้น handheld · เก็บระดับเครื่องใน `KvMeta` จึงอยู่รอดข้ามปิด-เปิดแอปและข้าม sign-out (เครื่องคลังใช้ร่วมกันหลายกะ) · pane เดียวกันมีการ์ดที่สอง **"จังหวะคีย์ที่วัดได้จากเครื่องยิง"** ท้ายรายการ — อ่านช่องไฟระหว่างอักขระที่วัดได้จริง (ต่ำสุด/กลาง/สูงสุด + ค่าดิบเรียงตามเวลา) เทียบกับเกณฑ์ `burstGap` ที่ใช้อยู่ พร้อมปุ่มล้างค่า **เป็นเครื่องมือวินิจฉัยอย่างเดียว ไม่มีอะไรในนั้นป้อนกลับเข้าเส้นทางสแกน**
